# ⑧ 会社に決めていただくこと（下書き）

| # | 決めること | 例 | 影響 |
|---|---|---|---|
| 1 | GCP プロジェクトと請求先 | `example-lattice` | 費用の付け先 |
| 2 | 置く地域 | `asia-northeast1`（東京） | データの所在 |
| 3 | ログインを許すドメイン | `example.co.jp` | 使える人の範囲 |
| 4 | 使う共有ドライブと、メンバーの権限 | `lattice_test` | 誰が編集・閲覧できるか |
| 5 | サンドボックスを us-central1 に置いてよいか | 置く（東京は未対応） | 計算中のデータが一時的に米国に置かれる |
| 6 | Gemini のデータの扱い（不正利用監視のオプトアウト、global エンドポイント、Web Grounding for Enterprise） | すべて採用 | データの保持・所在 |
| 7 | 1日の Gemini 利用上限（1人／全体） | 200万／1,000万トークン | 費用の上限 |
| 8 | 上限予算とアラートの金額 | Agent Platform 月4,000円、Cloud Run 月1,000円 | 使いすぎを止める |
| 9 | CPU を常時オンにするか | オン | 裏の作業が止まらない代わりに費用が増える |
| 10 | Terraform の状態ファイルの置き場所 | GCS のバケット | 会社では GCS のバケットを推奨 |
| 11 | 独自ドメインを付けるか | 付けない（run.app の URL） | URL の見た目、証明書の管理 |
| 12 | 資料の受け渡しの形 | Markdown | PDF・Google ドキュメントへの書き出し |
| 13 | 誰が運用するか（更新・障害対応・権限の追加） | 担当者 | ⑦ 運用手順の宛先 |
